# Отдельная платформа или раздел внутри `disklay`

**Контекст.** Задача была поставлена так: сделать отдельную платформу-тренажёр по гистологии, чтобы посмотреть, что получится лучше — отдельная или встроенная в основной анатомический тренажёр [`DISKLAY/disklay`](https://github.com/DISKLAY/disklay). Основной репозиторий намеренно не изменялся. Этот документ фиксирует выводы по сделанному прототипу.

> Важная оговорка: встроенный вариант **не реализовывался**. Ниже — оценка по архитектуре `disklay` (статический офлайн-сайт, `main#app`, hash-роуты, обычные `<script>`-банки, светлая/тёмная темы, `scripts/import_*_pdf.py`, локальный прогресс и награды) и по тому, что реально показал этот прототип. Это не A/B-замер двух работающих систем.

## Что было построено

| | |
|---|---|
| Репозиторий | `DISKLAY/Histologi_arm`, ветка `arena/acebe5c6-histologi-arm` |
| Формат | статический сайт, без сборки и сервера, `localStorage` |
| Источник | 3 PDF, слайды 113–426 (314 страниц) |
| Объём | 58 препаратов, 12 разделов, 272 снимка без подписей, 242 подписанных слайда, ~50 МБ изображений |
| Обработка | 105 кадров извлечены чистыми из XObject, 167 — с аккуратно удалёнными подписями |
| Функции | quiz (выбор / ввод), подсказки, разбор с подписанным слайдом, атлас с поиском, увеличение снимка, ошибки, избранное, статистика, две темы |

## Сравнение по критериям

| Критерий | Отдельная платформа | Встроенный раздел | Перевес |
|---|---|---|---|
| Специфика препарата | Пара «чистый / подписанный», zoom, окраска, бейдж «подписи удалены» заложены в ядро |Общий движок «вопрос → картинка → ответ» придётся расширять под новый тип медиа | отдельная |
| Общий прогресс | Своя статистика, между дисциплинами не складывается | Один профиль, единые сессии, награды, мотивация | встроенная |
| Обнаруживаемость | Нужна отдельная ссылка, отдельный репозиторий | Пункт меню там, где студент уже занимается | встроенная |
| Вес данных | Тяжёлый датасет и генератор изолированы | ~48 МБ и import-скрипты переезжают в основной проект | отдельная |
| Скорость итераций | Можно менять UX без риска для коллоквиумов по анатомии | Правки затрагивают общий роутинг, темы и банки | отдельная |
| Повтор кода | Свои темы, навигация, хранилище — часть дублирует `disklay` | Переиспользуются компоненты и формат банков | встроенная |
| Импорт новых препаратов | Скрипт читает PDF напрямую, схема данных простая | Нужно вписываться в чужие import-скрипты | отдельная |
| Поддержка | Две точки входа, два набора багфиксов | Один деплой, один набор проверок | встроенная |

## Что неожиданно показал прототип

1. **Разбор важнее самого ответа.** Гистологический препарат без подписей — это не «вопрос с одним правильным ответом», а изображение, которое надо уметь прочитать. Кнопка «Показать подписанный снимок» оказалась центральным элементом, а не дополнительной опцией. В анатомическом движке такого парного показа нет, и добавление его ломает абстракцию банка.
2. **Инструменты просмотра важнее режимов.** Увеличение снимка, фильтр по окраске и номеру препарата, просмотр всех кадров группы оказались нужнее, чем экзаменационный таймер или награды.
3. **Ошибки и избранное — универсальны.** Эти два блока почти не зависят от предмета; при встраивании их логично вынести в общий компонент и не писать второй раз.
4. **Подготовка данных — отдельный конвейер.** Извлечение XObject, склейка полос, выбор чистого кадра из пары, дедупликация и замазывание подписей никак не связаны с UI. Это аргумент в пользу отдельного репозитория-источника данных независимо от того, где будет жить интерфейс.
5. **Качество маскировки — ограничение, а не деталь.** 162 кадра обработаны автоматически (стираются только буквы, стрелки и ткань сохраняются), для них введён бейдж. Если встраивать такие данные в общий банк, эта метаинформация должна сохраниться.

## Рекомендация

**Гибрид.**

- Оставить `Histologi_arm` как **источник данных и полигон UX**: здесь лежат генератор, манифест и изображения, здесь удобно менять quiz и маскировку.
- В основной платформе сделать **тонкий раздел «Гистология»**:_IMPORT `window.HISTO_DATA` как ещё один банк, переиспользовать общие темы/навигацию/`localStorage`, но сохранить гистологические элементы (пара снимков, zoom, бейдж «подписи удалены»).
- Изображения не копировать в основной репозиторий: использовать внешнее хранилище или подключать `assets/` этого репозитория как подмодуль/статический источник.

Так получается единая точка входа и общий прогресс (сильная сторона встраивания) без раздувания основного проекта и без потери специфики препаратов (сильная сторона отдельной платформы).

## Как проверить экспериментально

1. Дать 5–10 студентам обе точки входа на неделю; замерить число сессий и число отвеченных препаратов.
2. Сравнить **долю возвращений** на второй день: отдельная ссылка против пункта меню в основной платформе.
3. Замерить долю сессий, где использовался подписанный слайд и подсказка, — это индикатор того, что разбор действительно работает.
4. Собрать список препаратов с максимальной долей ошибок и проверить, не являются ли они кадрами с неидеальной маскировкой (ложная сложность из-за обработки, а не из-за гистологии).
5. Только после этого решать: переносить манифест в основной проект или оставлять два продукта.

## Что осталось за рамками

- Реальная реализация встроенного раздела и замеры на пользователях.
- Медицинская сверка названий, номеров и окрасок с атласом кафедры.
- Текстовые страницы PDF (64 страницы описаний) как теоретический справочник.
- Общий экспорт/импорт прогресса между двумя платформами.
